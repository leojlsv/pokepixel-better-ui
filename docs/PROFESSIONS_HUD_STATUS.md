## Current native evidence

Product Owner live probe confirmed these getters exist on `PokeIdle.Api`: `getProfessions`, `getStamina`, `getFarmWorkforce`, `getFishingState`. It also confirmed native worker mutation APIs exist, including `assignProfessionWorker` and `unassignProfessionWorker` plus profession-specific assignment functions.

The Product Owner diagnostic v1 then confirmed the worker contract needed for the first real monitor. `getFarmWorkforce().data.workers[]` exposes `creature_id`, `creature_name`, `level`, `slot_index`, `stamina_basis`, `active_seconds`, `endurance_seconds`, `paused_reason` and related metadata; `candidates[]` exposes candidate identity, level and `stamina_basis`. `stamina_basis` uses a 0..10000 basis that is consistent with the same payload's feed `restore_basis` values; this candidate renders it as 0..100%. `active_seconds/endurance_seconds` supplies presentation-only autonomy. Zero stamina is determined from the authoritative observed worker field `stamina_basis === 0`, not from the countdown.

The same payload confirmed that top-level `getStamina()` is a different/global stamina contract (`stamina_ms`, `cap_ms`, accrual/farming flags) and is not used as an individual worker rotation trigger. `getProfessions().workforce` exposes `creatures`, slot counts and `slots.farmer/fisher/miner`, but the v1 diagnostic stopped one level before the slot worker fields. Diagnostic v2 now projects one bounded sample from each slot category plus assign/remove method arity/parameter names so the generic cross-profession rotation contract can be closed without executing a mutation.

The Product Owner diagnostic v2 resolved the **argument names/order**, not mutation outcomes: `assignProfessionWorker(professionId, creatureId, slotIndex)`, `unassignProfessionWorker(professionId, slotIndex)`, `assignFarmWorker(creatureId, slotIndex)`, `removeFarmWorker(slotIndex)`, `assignMiningWorker(creatureId, slotIndex)` and `removeMiningWorker(slotIndex)`. Generic `workforce.slots.farmer[0]` and `miner[0]` expose `creature_id`, `profession_id`, `slot_index`, `status`, `seconds_remaining`, `can_start`, `slot_available`, `recovery_seconds`, `recovery_required`, `recovery_percent` and `reward_claimed`; the sampled `fisher` array was empty. These generic slots do **not** expose the Farm worker's `stamina_basis` in the supplied sample, so generic status/recovery must not be inferred as Farm exhaustion.

## Automatic rotation feasibility

The Product Owner capability probe confirms native worker mutation methods exist, including `assignProfessionWorker`, `unassignProfessionWorker`, `assignFarmWorker`, `removeFarmWorker`, `assignMiningWorker` and `removeMiningWorker`. That makes an authoritative zero-stamina rotation technically plausible without inventing a custom network client.

Farm zero-stamina detection and reserve counting exist as a **read-only assessment**: an identified assigned worker is exhausted when `stamina_basis === 0`; an identified, unassigned candidate with `stamina_basis > 0` is monitor-ready, which does not prove native write eligibility. The current count/coverage assessment does not enforce unique active IDs/slots, known slot indices or non-paused workers and is **not implementation-ready as a mutation gate**. The code deliberately does not select a winner among multiple reserves because no authoritative ordering policy has been observed. Actual automatic replacement remains blocked on atomicity, authoritative revision/precondition or cross-tab serialization, mutation result/eligibility semantics, conflict handling, reservation/manual-override precedence, explicit replacement selection policy and authoritative post-write verification; method signatures alone cannot establish those behaviors.

## 0.2.98 corrective — observer stability and dense layout

An independent review caught an actual self-triggering reconciliation loop: the HUD wrote `open.disabled=true` on every reconciliation when the native Professions menu was absent, while the centralized observer reacts to `disabled` mutations. The implementation now writes the attribute only on state transition. Regressions cover native action disappearance/availability, direct attribute records and the actual central observer: it settles without repeatedly scheduling frames. The existing one-second autonomy display timer now also refreshes docking, which follows style-only changes to Team HUD z-index within the next presentation tick without adding another observer or native getter call. A delayed tick may briefly display the previous Team stacking value when the host throttles background timers; actual window precedence still requires user live validation.

The previous body `max-height:calc(min(46vh,420px) - 40px)` assumed the header occupied exactly 40px. Independent off-game Edge geometry evidence disproved that assumption with 30 worker rows and 40px coarse-pointer controls: the bottom diagnostic button could protrude beneath the clipped root even at maximum scroll. The corrective uses a flex-column root, a non-shrinking header and a `flex:1 1 auto;min-height:0;overflow:auto` body, allowing the real header height to determine remaining scroll area. Responsive/host-specific render evidence remains distinct from technical tests.

## 0.2.99 — Wallet exclusion and docking corrective (2026-09-28)

Product Owner live validation established that Backpack now covers Professions as intended, **but the panel did not respect the Wallet**. The preceding implementation preserved the DOM order `Professions → Team → Wallet`, yet computed the Professions rectangle solely from `Team.getBoundingClientRect()`. When the independently positioned Wallet appears below Team, `Team.bottom+8px` intrudes into the Wallet; the viewport-clamp fallback could also intrude into Team. The new `AC-17` explicitly requires visible Wallet clearance.

The `0.2.99` implementation reads the visible native Wallet **immediate sibling** bounding rectangle without changing its DOM, styling, dimensions, handlers or state. A pure docking planner uses Team and Wallet as independent keep-out rectangles, reserves an 8px gap and checks the **final** candidate for finite viewport position and both native collisions. It tries below the occupied rectangle, above it and available lateral space. When only a smaller vertical band is available, it limits panel height so the body scrolls while the header and a 40px coarse-pointer action remain reachable. If no usable rectangle fits, the optional Professions HUD temporarily yields space (hidden), while the original native Professions action remains available; it restores on subsequent reconciliation/resize/drag. Fully offscreen Team geometry fails closed and offscreen Wallet does not reserve nonexistent visible space.

The existing one-second presentation tick remains a backstop for style-only native movement. A passive native Team drag-handle pointerdown adds requestAnimationFrame-coalesced positioning during drag, with pointerup/pointercancel completion and exact cleanup; no new observer, mutation API call or gameplay automation is introduced. Stacking continues to share Team's native parent/z-index, preserving the already-observed Backpack behavior and the direct Team → Wallet CSS selector.

An additional adversarial gate found that repeatedly measuring an already-hidden header as zero could lower the calculated minimum panel height and cause alternating hide/show reconciliations in a narrow free band. The controller now retains its last positive native-rendered header height, makes hide/show transitions only when needed, and transfers keyboard focus to the native Professions action when a currently focused panel loses all safe space. A user-requested expansion in a short viewport that cannot fit a usable scrollport reverts to the visible collapsed header, retains focus and explains the limit through localized title/ARIA text. Native Team nodes with zero dimensions also fail closed, restoring when visible.

## 0.2.100 — Product Owner live rejection: Professions disappeared (2026-09-28)

Product Owner reported that the `0.2.99` Professions HUD was no longer locatable. **This rejects the 0.2.99 discoverability behavior**, irrespective of its earlier TECH/UX source gates. The native Wallet/Team no-overlap calculation was deliberately conservative, but choosing `root.hidden=true` whenever the *expanded* rectangle failed meant that the entire feature could disappear for realistic short or narrow screens; the user had no visible in-place recovery control.

The new presentation decision tree preserves the same native stacking layer/z-index and direct Team → Wallet sibling selector:

1. Show the expanded, body-scrollable Professions HUD when its minimum interactive area fits.
