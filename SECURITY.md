# Security policy

## Reporting a vulnerability

Do not publish exploit details, credentials or sensitive reproduction data in a
public issue.

After the repository is public, use GitHub's private vulnerability reporting
flow from the repository **Security** tab when it is available. If private
reporting is temporarily unavailable, open a minimal issue asking the maintainer
for a private reporting channel without including vulnerability details.

## Scope

Security reports should concern Better UI code or its build/development
configuration. Do not probe, attack or stress PokePixel or other third-party
services to demonstrate a Better UI issue. Prefer local source inspection,
synthetic fixtures and non-destructive reproduction.

The actively maintained branch is `main`; fixes are evaluated against the latest
supported Better UI version.
